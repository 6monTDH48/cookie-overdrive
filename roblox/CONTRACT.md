Goal: the Roblox game must look **exactly like the website** (`site/index.html`, sources in
`source/src/`). Roblox cannot draw SVG/canvas, so we export the site's art to PNG and rebuild it in
Roblox as images. No Roblox character, fixed full-screen 2D GUI like the site.

## 1. Asset keys
An asset key is a string. Keys = the site's own art names from `CO.art.names()` unchanged
(`ui:gem`, `tab:shop`, `b:cursor`, `boss:broccoli`, `egg:basic`, `item:milk`, `mg:ninja`,
`pet:hamster`, `vis:crown`, …: 121 names), plus these generated renders:

| key | what | size (px) |
|---|---|---|
| `cookie:<skinId>` | the cookie body for every skin in `roblox/src/shared/GameData.lua` (15 skins; `vip`, `robux`, `plasma` do not exist on the site: render them with the palette from GameData and styles `holo`, `classic`, `rainbow`), no accessories, drawn with the site's `CO.stage.drawCookie(ctx, x, y, r, {skin, simple:false, accessories:false, t:0})` | **640×640, cookie centred, radius r = 200 px** |
| `acc:<visKey>` and `acc:<visKey>_<lvl>` for lvl ≥ 2 | one cookie accessory alone, transparent background, in the **same 640×640 frame, same r = 200 centre**, so it overlays `cookie:*` exactly. Keys: every entry of stage.js `BODY_KEYS`, `TOP_KEYS` and `wings` | 640×640 |
| `bg:<themeId>` | the full stage background of each theme (synthwave, galaxy, matrix, candy, inferno, aurora) without cookie, HUD or particles, 16:9 | 1024×576 |
| `fx:<name>` | sprites for effects the GUI animates: `fx:glow` (soft white radial glow), `fx:ring` (shockwave ring), `fx:spark`, `fx:star`, `fx:god_rays`, `fx:black_hole`, `fx:saturn_back`, `fx:saturn_front`, `fx:disco_ball`, `fx:sun_synthwave`, … (the exporter decides; everything is listed in the manifest) | ≤ 512 |
| `golden` | the golden cookie as drawn on the stage | 256×256 |

SVG art (`ui:`, `tab:`, `b:`, …) is rendered at **128×128**, except `pet:*`, `egg:*`, `boss:*`,
`mg:*` and `item:*` at **256×256**. Hard limit: **no image larger than 1024 px on any side**
(Roblox EditableImage limit).

## 2. Files
- `roblox/assets/png/<file>.png`: file name = key with `:` replaced by `__` (e.g. `ui__gem.png`, `cookie__classic.png`).
- `roblox/assets/manifest.json`: `{ "<key>": { "file": "ui__gem.png", "w": 128, "h": 128 }, ... }`.
- `roblox/src/shared/ImageData/<file-stem>.lua` (generated by `roblox/tools/pack_assets.py`):
  `return { key = "ui:gem", w = 128, h = 128, z = "<base64 of zlib(raw RGBA8, row-major, unpremultiplied)>" }`
  plus `roblox/src/shared/ImageData/_index.lua` → `return { ["ui:gem"] = "ui__gem", ... }` (key → module name).
- `roblox/src/shared/AssetIds.lua`: `return { ["ui:gem"] = 0, ... }`. The ids of the uploaded
  images, filled later by the uploader. 0 means not uploaded.

## 3. Runtime image API (client): `roblox/src/client/Img.lua`
```lua
local Img = require(script.Parent.Img)
Img.has(key) -> boolean
Img.size(key) -> Vector2          -- pixel size from the index/module
Img.set(guiObject, key) -> boolean
--   guiObject is an ImageLabel or ImageButton. If AssetIds[key] ~= 0 → .Image = "rbxassetid://id".
--   Otherwise decode the ImageData module (base64 → inflate → RGBA buffer) into an EditableImage
--   (AssetService:CreateEditableImage{Size=...}, :WritePixelsBuffer) cached per key, and set
--   .ImageContent = Content.fromObject(editable). Returns false (and leaves the object unchanged)
--   if the key is unknown or creation failed, so callers can fall back to an emoji.
Img.preload(prefixes: {string}?)  -- decode in the background (task.spawn, yields between images)
```
Decoding must be lazy and cached. Never block the first frame for more than a few ms.

`source/src/js/stage.js`. Colours: bg `#0b0620`, ink `#fff6fe`, muted `#b3a6dd`, dim `#7d6fae`, stroke
